# حماية صفحات نظام إدارة الدفعات — تعليمات مهمة

**لا يمكن منع عرض مصدر HTML أو JavaScript أو الصور في موقع GitHub Pages.** أي ملف يصل للمتصفح يمكن نسخه، وتعطيل F12 أو الزر الأيمن لا يوفّر حماية.

## ما الذي يفعله هذا التحديث؟
- `server.js`: يضيف `Cache-Control: private, no-store` إلى كل ردود `/api` الموثقة لمنع تخزين بيانات المتدربين في ذاكرة المتصفح أو وسطاء التخزين. يحافظ على `helmet` والتحقق من JWT والصلاحيات.
- `index.html`: يحافظ على آخر إصلاح للقوالب وتنزيل PDF باسم المتدرب، ويضيف سياسة Referrer آمنة. لا يمنع عرض المصدر، ولا يدّعي ذلك.
- `secure-other-pages.py`: يُضيف وسم سياسة Referrer إلى جميع ملفات HTML الأخرى محليًا، دون تغيير JavaScript أو وظائف الصفحة. شغليه داخل مجلد المستودع: `python secure-other-pages.py`.

## التركيب
1. احتفظي بنسخة احتياطية من `index.html` و`server.js` قبل الاستبدال.
2. استبدلي الملفين في جذر `Control-Panel`، وضعي السكربت بجانبهما.
3. شغّلي السكربت اختياريًا لتحديث صفحات HTML الأخرى.
4. من GitHub Desktop: Fetch/Pull إن طلب، ثم Commit وPush. تأكدي من اكتمال نشر Render لخادم `server.js`.
5. اختبري تسجيل الدخول، والبحث، والقوالب، وتنزيل PDF وسجل الإصدارات.

## الحماية الفعلية المطلوبة
- أبقي مفاتيح `service_role` وكلمات مرور PostgreSQL وJWT secrets في Render Environment فقط؛ المفتاح `anon/publishable` عام بطبيعته.
- اجعلي كل عمليات البيانات الحساسة في Render مع فحص الصلاحيات؛ لا تعتمدي على إخفاء أزرار الواجهة.
- فعّلي RLS على جداول Supabase، وراجعي صلاحيات الأدوار، وقللي ظهور البيانات في سجلات الأخطاء.
- إذا أردتِ عدم كشف شفرة التطبيق نفسها، انقلي منطقها الخاص إلى الخادم، ولا تضعيه في JavaScript المنشور. ويمكن تصغير الشفرة/تشويشها لتصعيب قراءتها فقط، لا لإخفائها.
- مستودع GitHub العام يعرض ملفات المصدر للعموم، بصرف النظر عن نطاق الموقع.
