# نظام إدارة المتدربين — نموذج آمن

الملف المرفق يحتوي على بيانات شخصية؛ لذلك **لا تُرفع نسخة Excel إلى GitHub**.

## البنية
- `index.html`: واجهة عربية متجاوبة، بلا بيانات شخصية مضمنة.
- `schema.sql`: قاعدة PostgreSQL مع سياسات عزل الصفوف.
- `server.js`: خادم Node.js يتطلب تسجيل الدخول عبر Supabase JWT، ويتيح البحث والتصدير والطباعة وفق الأدوار.
- `import.py`: أداة استيراد محلية من ملف Excel إلى قاعدة البيانات (لا تُرفع البيانات نفسها).

## التشغيل
1. أنشئ مشروع Supabase خاصًا، وشغّل `schema.sql` في SQL Editor.
2. أنشئ حسابات المستخدمين من لوحة Supabase Auth. لا تفتح التسجيل العام.
3. أنشئ حساب مستخدم مشرف، وأضف معرفه UUID إلى `app_roles` بدور `admin` عبر لوحة SQL.
4. اضبط متغيرات الخادم: `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `DATABASE_URL`, `ALLOWED_ORIGIN`.
5. شغّل `npm install && npm start` على استضافة Node.js تدعم HTTPS، مثل Render. لا تضع متغيرات الخادم السرية في GitHub Pages.
6. استورد البيانات محليًا بعد ضبط `DATABASE_URL`: `pip install openpyxl psycopg[binary]` ثم `python import.py '/path/to/file.xlsx'`.
7. انشر `index.html` على GitHub Pages بعد ضبط `API_BASE` و`SUPABASE_URL` و`SUPABASE_ANON_KEY` (المفتاح العام فقط) داخل الصفحة.

## ملاحظات أمنية
- مستودع GitHub يجب أن يحتوي على الشفرة فقط، دون Excel أو نسخ قاعدة البيانات أو مفاتيح الخادم.
- حسابات `viewer` للبحث والعرض فقط، `exporter` يسمح بالتصدير والطباعة، `admin` كذلك.
- المتصفح لا يمكن حمايته من فحص المصدر؛ الحماية الحقيقية هي عدم إرسال البيانات إلا للمستخدم المصرح له.
- من لديه إذن رؤية البيانات يستطيع نظريًا تصويرها أو نسخها؛ لا يمكن منع ذلك تقنيًا منعًا مطلقًا.
- راجع متطلبات نظام حماية البيانات الشخصية السعودي قبل الاستضافة، وحدد سياسات الاحتفاظ والوصول.
