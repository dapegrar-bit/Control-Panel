# نظام إدارة بيانات الدفعات — النسخة المصححة

## أهم الإصلاحات
- `config.js` أصبح المصدر الوحيد لإعدادات واجهة الموقع، مع ضبط عنوان Supabase ورابط Render.
- يلزم إدخال **مفتاح Supabase العام** يدويًا في `config.js` قبل عمل تسجيل الدخول. لا تضعي أي مفتاح سري.
- يستخدم `server.js` جدول `app_private.user_roles` الموجود مسبقًا للتحقق من الدور.
- أُلغي مسار إنشاء المدير العام وصفحة الإعداد، لأن المدير موجود بالفعل.
- `GET /health` يفحص تشغيل الخادم فقط، ولا يفحص اتصال قاعدة البيانات.
- `schema.sql` ينشئ جدول السجلات إن لم يكن موجودًا ولا يعبث بجدول الصلاحيات الحالي.

## النشر
1. افتحي `config.js` واستبدلي `PASTE_PUBLIC_SUPABASE_KEY_HERE` بمفتاح anon أو publishable العام من Supabase.
2. ارفعي الملفات المعدلة إلى مستودع GitHub. يجب أن تتحدث نسخة Render تلقائيًا أو أعيدي نشرها يدويًا.
3. في Render تأكدي من `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `DATABASE_URL`, `ALLOWED_ORIGIN` (الرابط الدقيق لـ GitHub Pages).
4. افتحي `/health` على Render. ثم افتحي `/api/sheets` دون تسجيل دخول؛ يجب أن يرد 401.
5. افتحي GitHub Pages وسجلي الدخول؛ إن ظهر 403 راجعي صلاحية المدير في `app_private.user_roles`؛ إن ظهر 500 راجعي سجل Render والجداول والاتصال.
6. تأكدي من وجود `public.trainee_records`، ونفذي SQL فقط بعد مراجعة الجدول الحالي.

## حماية البيانات
لا ترفعي بيانات Excel الحقيقية قبل مراجعة المتطلبات النظامية ومكان تخزين البيانات والنسخ الاحتياطية واختبار الأدوار. لا تضعي DATABASE_URL أو service_role أو كلمات المرور في GitHub.
